# Evaluation Protocol

**Frozen before any agent exists.** Everything in this document was fixed before the
baseline was written, so the metrics cannot be reshaped later to flatter a result. If
something here turns out to be wrong, it changes by an explicit, dated amendment in
§10 — never by a silent edit.

Acceptance bar for this document: a second person could read it, score a run, and get
the same numbers without asking a single question.

---

## 1. The task

Given a **job posting** and a **candidate profile** (`data/profile/candidate.yaml`),
decide whether the posting is worth the candidate's time, and cite the evidence.

Both the baseline and every agent variant emit the same JSON:

```json
{
  "verdict": "SKIP",
  "blockers": [
    {"type": "work_authorization",
     "evidence": "We are unable to provide visa sponsorship for this position."}
  ],
  "caveats": []
}
```

`type` must be one of the 14 ids in `data/taxonomy.yaml`. `evidence` must be a
**verbatim** quote from the posting.

---

## 2. The corpus

24 synthetic postings, generated by `src/injector/generate.py` at `CORPUS_SEED=42`.

| Bucket | Count | Gold verdict |
|---|---|---|
| Injected, single blocker | 10 | SKIP |
| Clean, with near-miss distractors | 8 | APPLY |
| Contradictory (title/body conflict, scoped negation) | 4 | SKIP |
| Multi-blocker stress | 2 | SKIP |
| **Total** | **24** | 16 SKIP / 8 APPLY |

Ground truth comes from construction, not judgment: the injector records the blocker
type, the character span it inserted, and the sampled parameter value for every
injection. Labels live in `data/corpus/labels.yaml`.

---

## 3. Matching a prediction to ground truth

Applied per posting, by `src/eval/match.py`.

**Normalization.** Collapse all whitespace runs to a single space and strip both the
posting and every quoted `evidence` string before comparing. Substring search is
case-insensitive. Quotes must be contiguous — an elided or paraphrased quote does not
match, and the prompt tells the system to quote verbatim.

**Detection matching is by `type` only, one-to-one.** Walk the predicted blockers in
order; each one matches the first not-yet-matched gold blocker of the same type on that
posting.

- **TP** — a predicted blocker matched a gold blocker.
- **FP** — a predicted blocker matched nothing (wrong type, or a duplicate of a type
  already matched, or a blocker on a clean posting).
- **FN** — a gold blocker no prediction matched.

**Evidence is scored separately, over the TPs only.** Locate the quote in the posting:

- Not found → **hallucinated evidence**.
- Found → compute its span `[a, b)`. It is **correct** if it overlaps the gold span
  `[c, d)`, i.e. `a < d and c < b`.

Detection and evidence are deliberately not collapsed into one number. An iteration that
leaves detection flat while raising evidence accuracy has done something real, and a
single combined metric would hide it.

---

## 4. Primary metric

**Micro-averaged detection F1** over all blocker instances in all 24 postings. Pool
TP/FP/FN across postings, then:

```
precision = TP / (TP + FP)
recall    = TP / (TP + FN)
F1        = 2 * precision * recall / (precision + recall)
```

If `TP + FP == 0`, precision is 1.0 by convention (nothing was claimed, so nothing was
wrongly claimed). If `TP + FN == 0`, recall is 1.0. If both precision and recall are 0,
F1 is 0.

Recall alone is not the primary metric, and this is deliberate: a system that flags every
posting scores perfect recall and is worthless, because the candidate is back to reading
all 24 by hand.

---

## 5. Secondary metrics

| Metric | Definition |
|---|---|
| **Clean-posting false-alarm rate** | Clean postings with >=1 predicted blocker, / 8. The user-facing cost of crying wolf. |
| **Decision accuracy** | Postings whose predicted verdict equals the gold verdict, / 24. |
| **Evidence-found rate** | TPs whose quote was located in the posting, / TPs. |
| **Evidence-correct rate** | TPs whose quote was located *and* overlaps the gold span, / TPs. |
| **Hallucination rate** | Predicted blockers that supplied a quote which was **not found** in the posting, / all predicted blockers. Computed over every prediction, not just TPs, so fabricated quotes inside false positives are counted too. |
| **Missing-evidence rate** | Predicted blockers that supplied **no quote at all**, / all predicted blockers. Reported separately from hallucination — see amendment 2026-08-30. |
| **Human time per task** | Section 7. |
| **Cost per task** | Total USD from `response.usage` across every call for a posting, / 24. |

**Verdict mapping.** `APPLY_WITH_CAVEAT` is scored as `APPLY`. Gold verdicts are only
ever SKIP or APPLY, so a three-way comparison would require judging when a caveat is
"deserved" — exactly the judgment call this document exists to eliminate. Caveats remain
useful product output; they are not scored.

**Per-type breakdown** (recall by blocker id, and by phrasing style: explicit / indirect /
footer) is reported as a diagnostic. It is not a headline number, but it is what tells you
*which* iteration to write next.

---

## 6. Target

Defined now, before any result exists. A good final system:

- **Recall = 1.00** — every gold blocker caught.
- **Clean-posting false-alarm rate <= 0.125** — at most 1 of 8 clean postings flagged.
- **Evidence-correct rate = 1.00** — every reported blocker cites a span that actually
  contains it.
- **Hallucination rate = 0.00** — no fabricated quotes, ever.

Anything less means the candidate either still wastes time, or stops trusting the tool.

---

## 7. Human time protocol

Measured once, by hand, with a stopwatch.

1. **Manual condition** — postings `jd_01`-`jd_10`, profile open alongside. For each:
   read it, decide APPLY or SKIP, and note any blocker found. Stop the clock at posting 10.
2. **Assisted condition** — postings `jd_11`-`jd_20`, reading the final system's output
   and deciding whether to accept its verdict.

Report total seconds / 10 for each condition.

**Stated limitation, not hidden:** n=1, self-timed, by someone who already knows the
corpus. This is a directional figure, not a controlled study, and the report says so.

---

## 8. Run protocol and variance

Outputs are **not** bit-reproducible — sampling parameters were removed on this model
generation and there is no temperature control (see `plan.md` section 13).

- Baseline: **3 runs.** Final: **3 runs.** Report the median as the headline and the
  min-max spread alongside it.
- Intermediate iterations: 1 run each, to conserve budget.
- **No improvement smaller than the observed baseline spread may be claimed as a result.**
  If the baseline varies by 5 F1 points across its 3 runs, a 3-point iteration gain is
  noise and must be reported as inconclusive.

---

## 9. Fairness invariants

Held identical between the baseline and every agent variant:

- Model (`MODEL_ID`) and effort (`EFFORT`)
- Corpus (`CORPUS_SEED=42`) and candidate profile
- The 24 postings, in the same order
- Scoring code — one `src/eval/` harness scores everything

The baseline receives the posting, the profile, and the bare list of 14 blocker ids —
names only. It does **not** receive their descriptions, phrasings, blocking rules,
per-category decomposition, a verification pass, a structured output schema, or any
requirement to cite evidence. That is what makes it a baseline. Its reasoning is never
tuned to make its output easier to parse — only the parse layer adapts, never the prompt.

The `claude-opus-5` spot-check is a **separate, labelled experiment** on the final
configuration only. It never appears in the baseline-vs-final comparison, because a
model change there would invalidate it.

## 10. Amendments

Changes to this protocol after the baseline is measured go here, dated, with the reason
and the effect on already-recorded numbers. An empty section at submission is the
expected outcome.

### 2026-08-30 — split missing evidence out of the hallucination rate

**Was:** hallucination rate counted every predicted blocker "whose quote was not found in
the posting", which includes blockers reported with no quote at all.

**Now:** hallucination counts only blockers that supplied a quote that could not be found.
Blockers with no quote are counted under a separate missing-evidence rate.

**Why:** the baseline is deliberately never asked for evidence (section 9), so under the
original wording it would have scored close to a 100% hallucination rate — reported as if
it were fabricating quotes, when it had simply not been asked for any. That would have
overstated the agent's advantage on a metric where the baseline was never competing.
Fabricating a citation and declining to give one are different failures and now read as
different numbers.

**Effect on recorded numbers:** none. The amendment predates the first baseline run;
no measurement existed when it was made.

### 2026-08-30 — the baseline is given the blocker id list

**Was:** section 9 said the baseline gets "no taxonomy".

**Now:** it gets the 14 blocker ids as bare names, and nothing else about them.

**Why:** detection is matched on those ids (section 3). A baseline that has never seen
them cannot emit one, so its recall was **0 before the first API call** — a guaranteed
result rather than a measurement. Every gain over it would have been an artefact of
vocabulary, not of engineering, and the comparison would not survive a judge asking how
the baseline was supposed to name a blocker it had no word for.

This makes the baseline stronger and the reported improvement smaller. The remaining
differences — decomposition, verification, evidence, structured output — are the ones
the iterations are actually testing.

**Effect on recorded numbers:** none; predates the first run.

### 2026-08-30 — conventions for undefined rates

**Added, not changed.** Section 4 fixed the zero-denominator conventions for
precision, recall and F1 but left three cases open. Filling them in, since the
acceptance bar for this document is that a stranger scores a run identically:

- **Evidence-found, evidence-correct** — reported as `n/a` when there were no true
  positives. A system that detected nothing has no citation quality to measure, and
  printing `0.0` would read as "cites badly" rather than "never cited".
- **Hallucination, missing-evidence** — reported as `n/a` when no blockers were claimed
  at all, for the same reason.
- **An unreadable answer matches no verdict.** A prediction that could not be parsed is
  scored as `UNREADABLE`, which equals neither gold verdict. Any concrete fallback hands
  out free credit — `SKIP` is right on the 16 blocked postings, `APPLY` on the 8 clean
  ones — and a system that emitted nothing legible decided nothing. Its blockers still
  count as missed.
- **A run with zero scored postings is refused, not scored.** Section 4's conventions
  compose to precision 1.0 and recall 1.0 on an empty corpus, giving F1 = 1.0 — so a run
  that crashed before scoring anything would report a *perfect* result. `aggregate()`
  raises instead. No postings scored is a failure, not a score.

**Effect on recorded numbers:** none; predates the first run.

---

## 11. Out of scope

Not measured, and not claimed: latency, UX quality, performance on real (non-synthetic)
postings, generalization to non-software roles, or any judgment of the candidate.
